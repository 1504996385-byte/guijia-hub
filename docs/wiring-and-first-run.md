# 接线与首次上板

本项目按T5-E1-Touch-AMOLED-1.75精确板型准备。开发期间USB供电，四个开关模块3.3V、SR505为5V。2026-11-06已完成外设连接、磁吸方向及实体录音保存/播放实测，当前音量90版已烧录并整幅回读一致；详见hardware-test-assembled-20261106.md。接线前先断开USB和电池供电。

## 固定接线

以板子丝印/官方原理图识别引脚，下面名称不是排针物理序号，更不是文档旧版中的GPIO1–5。

| 功能 | 板上信号 | 软件默认 |
| --- | --- | --- |
| 我：钥匙归位检测 | IO14 | 本次实测高电平=磁铁归位，60ms稳定防抖 |
| TA：钥匙归位检测 | IO15 | 本次实测高电平=磁铁归位，60ms稳定防抖 |
| 给我留言：实体瞬时按键 | IO16 | 本次实测高电平=按住；松开保存 |
| 给TA留言：实体瞬时按键 | IO17 | 本次实测高电平=按住；松开保存 |
| 本次 SR505 OUT | IO47 | 高电平=感应，本次装配版缺省启用 |
| 聊天（新准备版） | 板载KEY / IO12 | 无需外接，低有效，按住说话、松开发送 |

裸干簧管和无源瞬时按钮可作为信号与GND之间的开关，输入使用上拉。带电路的传感器/按钮模块，须先确认VCC/GND/S或D0丝印及输出电平，再按模块说明连接；不能把三针/四针模块当裸开关随意接线。首次上板需验证实际模块是否低有效，不符合默认时调整配置/驱动后重新验收。

2026-11-06 用户确认实际外设：两个干簧管模块各为 GND/VCC/D0；两个实体按钮模块各为 GND/VCC/OUT。对应两个 D0 分别接 IO14/15，两个 OUT 分别接 IO16/17；GND 共地，四模块3.3V，不向 IO 直接输入5V。实板日志与用户操作均证实四路均为高有效，已修正旧版反向逻辑；旧版日志不能当作修正后的验收。

另有独立红外接收/发射模块，各标 GND/VCC/S；用户描述接收端为黑色小接收头，发射端为小灯珠。外观更像遥控红外收发类，未确认具体型号，不能视作 PIR，也未分配或启用它们。若需人体靠近唤醒，建议补充与 IO47 电平匹配的 PIR 移动检测模块；PIR 不保证静止在场检测。此功能的实际模块和验收仍待确定。

PIR实际到手且电平确认后再启用。38kHz红外接收器、发射管及槽型光电开关不作为PIR替代。PIR热机60秒，语音提醒间隔180秒；它不承担留言主链路。

### 本次 SR505 人体感应模块

用户实物照片可辨认 `SR505` 丝印及白色菲涅尔透镜。该型成品模块的资料为供电 DC4.5–20V、输出高3.3V/低0V；因此 **模块 VCC/+ 使用板上5V，信号 OUT 接 IO47，GND/− 共地**。这与前面可用3.3V供电的开关模块不是同一供电规则。按实物丝印核对，不按线色或照片左右猜接。用户目前表示引脚标记看不清、保持未接，尚未实测。

来源：[Okystar HC-SR505 成品模块规格](https://okystar.com/wp-content/uploads/2017/07/OKY3271-1.pdf)、[Microchip AN2387 第4–5页](https://ww1.microchip.com/downloads/aemDocuments/documents/OTH/ApplicationNotes/ApplicationNotes/00002387B.pdf)。SR505 检测人体活动，不能识别人、判断进出方向或保证持续静止在场。

最新用户需求为“人走到门口、没有拿钥匙时提醒拿钥匙”。开发分支正准备独立匿名提醒：任一槽位钥匙仍在则固定播 take_key.wav；无钥匙只唤醒；录音/留言优先、等待最多10秒、提醒间隔180秒。PIR不会触发个人信箱。当前已烧录镜像还是 hardware-test-20261106.md 记录的01e04494版本，PIR默认关闭；新候选需与该实板记录分别验收。

另一张配件袋照片无法辨认毫米波雷达型号，不能据此分配供电或串口。此轮先使用已确认的 SR505；不同时接入雷达。

此版不接外部RGB灯，用屏幕暖色背景表现暖光。外接灯条需要另核算IO与驱动。

## TF卡

使用与官方示例兼容的FAT32卡；准备工具仅复制素材，不格式化、不删除卡上文件。将项目sdcard目录的homehub目录放到卡根。voices内已准备普通话系统合成测试语音，manifest.json明确标注，不是真人方言。

当前固件已内置三条基础普通话测试素材，启动时只向已挂载的卡补充缺失的 arrive.wav、leave.wav、take_key.wav，不覆盖现有文件。本次实板已验证首次写入与重启保留；不等于已完成扬声器出声或 TF 断电恢复验证。

已存在的config.json、录音及同名语音由卡准备工具保留。首次联网配置按固件最终README填写；空联网配置用于离线主线。

## 交互与验收

1. 启动时只读取两个槽位状态，不把已有钥匙误当刚回家。
2. 默认根据接收人槽位选择下一次取走/归位；给自己晚间提醒时，先在屏幕预选“下次归位”，再按住自己的实体按钮录音。
3. 按住实体按钮说话，松开保存；短于250ms不保存，最长30秒。存储失败时须显示失败，不能出现假“已保存”。
4. 对应钥匙事件发生后播放待播留言，成功完整播放才标已播；没有留言时播放普通话测试问候。
5. 完整验证取走与归位、晃动不重复播、两槽依次操作、重启后录音保留、录放互斥、断网基础功能。
6. 最后装入外壳和真实钥匙再次测试磁场串扰、喇叭影响、按键、电源和声音。

没有联网配置时不显示虚构天气或AI结果。手机跨网远程使用需要后续配置可访问服务器与HTTPS，并不由烧录自动完成。

## 语音聊天准备版

本轮聊天代码使用板载KEY，两个外接按钮保持留言用途。等待/回答时再次按KEY取消。未授权或服务未就绪时不采集，屏幕显示实际原因。采集最大30秒、少于250ms取消、等待回答45秒超时；确实停止本地音频后才交还留言。本轮新候选与此前实际上板版本分开保存，详见voice-chat-report.md。

授权从板内读取，不需要把密钥发到聊天。TF的chat_enabled默认true；tuya_product_id默认官方微雪示例开发PID，可按现场产品配置更改。本次装配版PIR缺省启用：config.json不存在或缺字段均启用，显式false仍保留。启动日志HH config会报告实际开关，HH inputs会报告防抖后的四个开关、PIR和板载KEY状态，1=有效；真实模块极性须上板核实。
